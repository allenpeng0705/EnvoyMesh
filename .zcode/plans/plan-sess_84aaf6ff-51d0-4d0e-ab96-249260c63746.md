# Make OpenClaw Gateway Startup Stable and Robust

## Problem
The OpenClaw gateway has failed at every DMG release with a different error:
1. `pnpm prune --prod` orphaned packages → `ERR_MODULE_NOT_FOUND` (json5)
2. rsync `--exclude config` stripped `dist/config/config.js` at every depth (4,808 files)
3. EnvoyMesh extension `.ts` sources never compiled (git ls-files didn't see copied extension)
4. No restart cap → watchdog loops forever on permanent failures
5. Silent build failures (esbuild errors suppressed with `2>/dev/null`)
6. No actionable error messages — generic "Gateway not reachable after 90s"

## Changes — 3 layers of defense

### Layer 1: Build-time — fail loudly, never ship broken bundles

**`scripts/stage-tauri-openclaw-bundle.sh`:**
- Make esbuild failures visible: remove `2>/dev/null`, check exit code, abort if compilation fails
- After esbuild, verify `index.js` was actually produced — abort if missing
- After rsync + node_modules copy, do a quick sanity count (file count in dist/ must be >10,000) — warn and suggest `STAGE_OPENCLAW_BUNDLE=1`

**`scripts/verify-tauri-resources.sh`:**
- Add `require_file` for `openclaw/extensions/envoymesh/index.js` (compiled extension)
- Add `require_file` for `openclaw/dist/cli/run-main.js` (critical runtime import)
- Add node_modules package count threshold: `node_modules/` must have >500 directories

### Layer 2: Runtime — pre-flight checks before spawning

**`apps/node/src/openclaw-gateway-spawn.ts` — new `validateOpenClawTree()` function:**
- Check `dist/entry.js` exists and is not a stub (already done)
- Check `node_modules/` has critical packages: `openclaw/package.json`, `json5`
- Check `extensions/envoymesh/index.js` exists (compiled extension)
- Check `dist/config/config.js` exists
- Returns `{ ok: true }` or `{ ok: false; missing: string[] }` with actionable list
- Called in `spawnOpenClawGateway()` before `spawn()` — if validation fails, throw a clear error listing all missing files (not just a generic "OpenClaw not found")

**`apps/node/src/openclaw-gateway-spawn.ts` — safer stub fallback:**
- In `ensureOpenClawEntryBootstrap()`, when writing a stub that falls back to `../src/cli/run-main.ts`, check if we're in a Tauri bundle (`TAURI_RESOURCE_DIR` or `TAURI_APP_RESOURCES_DIR` env var is set). If so, don't write the `.ts` fallback stub — log a clear error instead. The `.ts` path will never work in a Tauri bundle since `src/` is excluded.

### Layer 3: Runtime — cap restarts and surface actionable errors

**`apps/node/src/node-service-openclaw-runtime.ts` — restart cap:**
- `consecutiveRestartFailures` counter already exists (line 175) but is never checked
- Add a cap: `MAX_CONSECUTIVE_RESTARTS = 5`
- In `startOpenClawInner()`, before spawning, check: if `consecutiveRestartFailures >= 5`, refuse to restart, log a clear error with the last failure reason, and stop the watchdog. The user must fix the root cause (reinstall, check config) before retrying.
- Reset counter on successful ready (already done in `clearOpenClawError()`)
- Add `RESTART_BACKOFF_MS = 10_000` — after the first failure, wait 10s before restarting; 20s after second; cap at 60s. Prevents tight restart loops burning CPU and flooding logs.

**`apps/node/src/node-service-openclaw-runtime.ts` — better error diagnostics:**
- In the startup probe timeout (line 703-709), include the last few stderr lines from the gateway in the error message. Currently it just says "port may be in use" which is misleading — the port might be fine but the gateway crashed on startup.
- Store the last N stderr lines in `state.lastGatewayStderr: string[]` (ring buffer, 10 lines). Updated by the stderr listener (line 1267). Used in error messages.
- Classify exit codes: code 1 with `ERR_MODULE_NOT_FOUND` in stderr → "Missing package — reinstall the app". Code 1 with `EADDRINUSE` → "Port conflict — set ENVOYMESH_PORT_OFFSET".

## How it works after the fix

**Build time:** If the extension fails to compile, or critical files are missing, the build aborts with a clear error — no broken DMG is ever produced.

**Runtime — first start:** `validateOpenClawTree()` catches missing files before spawning. If something is wrong, the error says exactly what's missing (e.g., "Missing: extensions/envoymesh/index.js, dist/config/config.js") instead of a cryptic module error after spawn.

**Runtime — crash loop:** If the gateway keeps crashing, after 5 consecutive failures the watchdog stops and logs: "Gateway failed 5 consecutive times. Last error: ... Fix the issue and restart EnvoyMesh." No more infinite restart loops.

**Runtime — slow start:** The 90s probe timeout remains (sufficient for properly compiled bundles). If it times out, the error now includes the gateway's actual stderr output, making diagnosis immediate.
