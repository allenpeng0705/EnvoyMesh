5. **Proposed design**
   - 5.1 **URL scheme spec** — `envoy://{owner}/{path}`, owner-id form in v1, `@handle` reserved v2. Parsing rules, disambiguation from `envoy://contact?`, encoding rules, examples. **The keystone decision — most space here.**
   - 5.2 **Content model** — `~/EnvoyMesh/web/` directory, manifest extending `VaultContentManifest` with `kind`/`mimeType`/`summary`/`visibility`/`updatedAt`/`urlSlug`. Templated site types (Profile / Blog / PhotoWall / Feeds) as conventions, not new schemas. Manual Markdown support. Raw file serving (PDF/image/word).
   - 5.3 **Visibility model** — per-item flags mapped to existing Bonds tiers. No tokens in URLs. Single URL works for bonded (sees content) and stranger (sees 403/redacted).
   - 5.4 **Protocol — one new intent pair** — `library.read` / `library.read.response`. Full Zod schemas. Bond-tier gating table. Byte/streaming caps.
   - 5.5 **Discovery** — extend `LibraryFileMatchSchema` with `kind`/`mimeType`/`summary`/`visibility`/`urlSlug` (additive, backward compatible). New capability string `"envoymesh.web-content"` alongside `"envoymesh.published-library"`.
   - 5.6 **Mobile architecture** — both modes documented with file:line refs.
   - 5.7 **Client (browser) UX** — Browser view in Social UI + EnvoyGo. Address bar, link handling, back/forward, render pipeline, bookmarks.
   - 5.8 **Authoring UX** — in-app editor for templated sites + Markdown, per-item visibility selector, publish button.
6. **Security model** — trust gating per-tier table, path safety (reuse `assertPathInsideVault`), abuse prevention (rate limits, byte caps, replay protection — all reuse existing guards).
7. **Threat model** — explicit enumeration: malicious publisher, malicious reader, relay tampering, content leakage, path traversal.
8. **Phased rollout** — the user's two-step plan, five sub-phases:
   - **45A** — URL scheme + parser + content directory + `library.read` intent + handler + Browser view (thin slice). **Includes ALL test layers per your choice** (see §9).
   - **45B** — Browser view polish + bookmarks + navigation history.
   - **45C** — EnvoyGo mobile Browser view + mobile→home→mesh request path.
   - **45D** — Authoring UX (templates + Markdown editor + per-item visibility + `web-content.json` manifest).
   - **45E (Step 2)** — `feed.notify` push, topic-based subscription, friend discovery. GossipSub decision explicitly deferred.
   - **45F (Step 3, future)** — External HTTP gateway (`--web-relay` mode). Out of scope for the immediate plan; forward reference only.
9. **Test plan** — **expanded heavily per your direction**. Four mandated layers for 45A:
   - **9.1 URL parser unit tests** — exhaustive coverage: valid owner-id URLs, `envoy://contact?` disambiguation, percent-encoding (CJK, spaces), malformed inputs (missing owner, empty path, bad scheme), `@handle` reserved form parses but rejects in v1 with clear error. Mirror `packages/api/test/` pattern. ~15–20 cases.
   - **9.2 Inbound handler trust tests** — mirror `knowledge-query-inbound.test.ts`. Per-tier behavior: stranger denied at non-public visibility, public-tier gets public-only, bonded gets friends, blocked denied, rate-limited, audit events emitted, path-traversal attempts rejected, oversized responses truncated. ~12 cases.
   - **9.3 Two-node vitest E2E** — mirror `library-publish-export-multi-node-e2e.test.ts` scaffolding verbatim (`createTestNode`, `registerBondedPeer`, `wireXxxHandler`, `connectPeers`). Bond A↔B, publish on A, `library.read` from B, assert bytes match. Add to `local-two-node-smoke.ts` smoke list. ~5 cases.
   - **9.4 Playwright full-stack E2E — comprehensive matrix** (per your choice). Spawns two real node OS processes via `NodeSpawner` (the Phase 38H-proven infra at `apps/social/test/e2e/helpers/node-spawner.ts`), opens Social UI in Chromium, drives the Browser view. **8 scenarios**:
     1. Fetch markdown → render `<h1>`
     2. Fetch image → render `<img>` with correct `src`
     3. Fetch PDF → render in `<iframe>`
     4. Stranger (third unbonded node) → 403 / access denied
     5. Bonded node → content served
     6. Back button navigates to previous page
     7. Malformed `envoy://` URL → error message in UI
     8. Bookmark a URL → re-opens from bookmark list
     - New file: `apps/social/test/e2e/web-content-browse.smoke.ts` (matches the Playwright `*.smoke.ts` glob in `playwright.config.ts:16`).
     - New helper if needed: extend `SocialPage` page object with `browseToUrl(envoyUrl)`, `expectRenderedContent(markdown)`, `expectAccessDenied()`.
     - Add `npm run smoke:web-content` script (mirrors `smoke:webrtc-call`).
   - **9.5 CI integration** — which tests run where: unit tests in `npm test`, two-node E2E in `npm run smoke:local`, Playwright in `smoke:web-content` (manual trigger initially, CI gate later).
10. **Verification scenarios** (the "simple scenario to verify the idea" you asked for) — **two, staged per your choice**:
    - **Scenario 1 (Phase 45A exit gate)** — single-doc drop: write `~/EnvoyMesh/web/hello.md` on Node A; on Node B (bonded), type `envoy://<A's owner>/hello.md` into Browser; assert `<h1>Hello</h1>` renders.
