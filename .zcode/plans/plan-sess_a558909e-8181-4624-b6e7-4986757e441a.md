# Add 18 Inline SVG Diagrams to the EnvoyMesh Guidebook (EN + ZH)

## Confirmed decisions
- **Scope:** All 18 diagrams (Tier 1 + Tier 2 + Tier 3)
- **Style:** Polished inline SVG cards — low-saturation fills, earth-tone borders matching the guidebook palette, clean connectors
- **ZH handling:** Separate EN and ZH diagram versions (each language gets native labels)

## Technical approach: inline SVG (the only viable option)

Verified that raw `<svg>` blocks pass through Python `markdown` unchanged (including embedded CJK text). Mermaid was rejected because it requires a JS runtime that breaks the self-contained HTML constraint and the pdf skill's "no hand-written Playwright" rule. Pre-rendered PNG loses vector/selectable text. ASCII is utilitarian but reads as engineering notes, not a product guidebook.

Inline SVG wins on every axis: vector (sharp at any zoom, selectable text in PDF), self-contained (native markup, no external assets), bilingual (uses the page CSS font stack), diffable in Markdown source, and pipeline-native (no extra dependencies or Playwright waits).

## Visual design system (locked)

- **Palette** (matches existing guidebook CSS variables):
  - Card fills: `#EFF6FF` (blue tint), `#F0FDF4` (green tint), `#FEF3C7` (amber tint for decisions/warnings), `#F5F5F4` (neutral)
  - Borders: `#3d5a45` (accent green), `#645a3a` (header brown), `#5d3ac7` (purple for highlighted paths)
  - Text: `#1e1d1b` (primary), `#6d6a63` (muted)
  - Connectors: `#6d6a63` at 1.2px stroke, arrowheads via `<marker>`
- **Typography:** `font-family="Inter, 'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', sans-serif"` so EN and ZH labels render identically to body text; node titles ≥13px, descriptions ≥11px, edge labels ≥10px (per pdf skill's embedded-diagram font floor)
- **Layout:** each SVG wrapped in `<figure style="display:block;width:100%;margin:3em auto;break-inside:avoid">` with a `<figcaption>` caption, satisfying the pdf skill's block-level-figure iron rule and preventing cross-page splits
- **Conventions:** named nodes with rounded rects (`rx="6"`), `subgraph`-style grouping via `<rect>` backgrounds with dashed borders, decision diamonds for branches, self-loops for cyclic flows, `[*]` start/end markers for state machines

## Production steps

### Step 1 — Build a shared SVG helper library
Write a Python module (`/tmp/gb_svg_lib.py`) with reusable functions: `card(x,y,w,h,title,subtitle,fill)`, `arrow(x1,y1,x2,y2,label)`, `decision(x,y,w,h,text)`, `state_node(x,y,text)`, `group(x,y,w,h,label)`, `wrap_svg(inner,viewbox,caption_en,caption_zh)`. This keeps all 18 diagrams visually consistent and the authoring manageable.

### Step 2 — Author all 18 EN diagrams
Insert each SVG block into `EnvoyMesh_GuideBook_0.1.0.md` at the section listed above, immediately after the H4 heading and before the prose. Each diagram carries an English caption.

### Step 3 — Mirror into ZH with Chinese labels
For each of the 18 diagrams, produce a ZH-labeled variant and insert into `EnvoyMesh_GuideBook_0.1.0.zh-CN.md` at the same section. Labels use the locked ZH glossary (智能体网络, 协作任务, 保险箱, 所有者, 中继, 工作节点, etc.). Captions translated.

### Step 4 — Regenerate HTML and PDF (both editions)
Re-run the existing converter pipeline (Python markdown → self-contained HTML → Playwright html2pdf-next.js → pypdf bookmarks/metadata). The SVG blocks render natively as vector PDF content. Add CJK-safe font stack to the SVG text elements.

### Step 5 — Validate
1. **SVG rendering:** confirm each `<svg>` block appears in HTML and renders in PDF (extract text from PDF, verify diagram labels present).
2. **Vector quality:** open PDF at 400% zoom on a sampled diagram — text must remain sharp (not raster).
3. **PDF QA:** run `pdf_qa.py` — must pass all hard checks (metadata, fonts, blank pages, overflow, margins, fill ratio). Low-saturation fills must not trigger color warnings.
4. **Cross-page safety:** no diagram split across pages (`break-inside:avoid` on `<figure>`).
5. **Skeleton parity:** 1162/1162 subsections preserved in both EN and ZH (diagrams are additive, not structural).
6. **Bilingual label check:** EN diagrams have English labels, ZH diagrams have Chinese labels; both render correctly.

## Diagram-content rules (from pdf skill)

Each diagram must satisfy:
- Connectors do not pass through nodes (adjacent-layer connections only)
- Multiple arrows into one node distributed, not piled
- Low-saturation fills only (no high-saturation color blocks)
- Phase titles vs sub-steps visually distinct (different fill color + font weight)
- Font sizes readable at A4 print scale (node title ≥13px, description ≥11px, edge label ≥10px)
- Legend/annotations separated from nodes with ≥40px gap
- ≤8 nodes per overview diagram (split complex flows into a simplified overview + a detailed sub-diagram if needed)
