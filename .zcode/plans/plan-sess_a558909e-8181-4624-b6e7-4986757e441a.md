# Fix: unreadable text on bright-green chat bubble and buttons

## Root cause (source-verified)

Two related contrast failures, both in the Social UI CSS:

1. **Outgoing chat bubble body text** — `color: var(--color-primary-on)` = `#ffffff` on a green gradient background `#07c160 → #06ad56` = ~3.0:1 contrast. WCAG AA needs 4.5:1 for body text. The bubble's time/badge use `rgb(255 255 255 / 0.78)` = ~2.5:1 — even worse.
2. **Buttons with the same background** — 36 other sites (ChatComposer send button, Discover "Around me" + "Say hello", search-result buttons, `.btn-primary` Save, `.tag`, etc.) all use `color: var(--color-primary-on)` = `#ffffff` on `var(--color-primary)` `#07c160`. Same ~3.0:1 contrast failure across the app.

The user confirmed: keep the bright green background, darken the text. Desktop Social UI only.

## The fix — one new token + token swap on body-text rules

### Step 1: add `--color-on-primary-text` to design-tokens.css

In both light and dark theme blocks, add a dedicated token for **body text / button labels on solid green fills**:

- **Light theme** (line ~88): `--color-on-primary-text: #052e16;` (near-black forest green; ~7:1 on `#07c160`)
- **Dark theme** (line ~180): `--color-on-primary-text: #052e16;` (same value; ~9:1 on the dark-theme mint `#34d399`)

Keep `--color-primary-on: #ffffff` UNCHANGED — it stays correct for icons, checkmarks, delivery status icons, avatar initials, and other small decorative elements where white reads cleanly.

### Step 2: switch body-text / button-label rules to the new token

Replace `var(--color-primary-on)` with `var(--color-on-primary-text)` ONLY at body-text / button-label sites. From the inventory:

**chat.css (4 sites):**
- Line 1638 (`.message-bubble.outgoing/.ai-outgoing/.outgoing-agent` body text) → new token
- Line 1525 (selection color inside ai-outgoing) → new token
- Line 1655 (`color-mix(... --color-primary-on 85% ...)` for outgoing-agent badge) → keep white (it's a small badge label, white reads OK, and the mix is intentional)
- Line 2888 (an icon button — keep white)

Also update the outgoing bubble's secondary text:
- `--message-outgoing-time` (design-tokens.css line 152, 238, 322): bump from `rgb(255 255 255 / 0.78)` to `rgb(5 46 22 / 0.78)` so time/badge labels on the green bubble are also readable.

**styles.css (28 sites):** switch the body-text/button-label rules. Skip avatar text initials (keep white) and icon-only buttons. Concretely, switch:
- Line 1202 (legacy `.message.outgoing` text) → new token
- Line 1283 (`.message.outgoing .message-text`) → new token
- Lines 1464, 1671, 1690, 1766, 2609, 2702 (button labels: ChatComposer send, Around-me, Say hello, search buttons) → new token
- Lines 5343-ish (`.btn-primary`) → new token
- Line 4889 / 5092 (`.tag` interest tags) → these are on `--color-primary-subtle` (light tint), not solid green; switch to `--color-on-primary-subtle` instead (the existing correct token for tint backgrounds), not the new solid-fill token.

Keep white at: avatar initials (lines 1026, 1736, 1833, 2655), icon-only buttons, `.message.outgoing` decorative shadow.

**ui-refine.css (1 site):**
- Line 1096 (`.discover-primary-btn, button.primary, .primary`) → new token

### Step 3: leave the tint-background sites alone

The "saturated green text on light green tint" sites (`.contact-list button.active`, `.locale-switcher__option.active`, settings tab hovers, etc.) are a SEPARATE contrast issue. The user did NOT complain about those — only the solid-green bubble + buttons. The design system already has `--color-on-primary-subtle` = `#047857` for those, and only 2 sites currently use it correctly. Out of scope for this fix; flagged for a future polish pass if the user reports it.

## Why this approach

- **Single source of truth**: one new token means future green-button contrast is enforceable — any new button just uses `--color-on-primary-text`.
- **Preserves icons**: `--color-primary-on: #ffffff` stays for icons/checkmarks/avatar initials where white is correct.
- **No visual disruption**: the green background is unchanged; only text color shifts from white to a dark forest green that reads cleanly. The "green button" identity is preserved.
- **WCAG AA compliant**: `#052e16` on `#07c160` ≈ 7:1 (passes AA for body text and AAA for large text).

- `npx vitest run apps/social/test/components/ChatMessageBubble.test.tsx apps/social/test/components/ChatComposer.test.tsx apps/social/test/components/Header.test.tsx` — no regressions (tests assert behavior, not exact colors).

- Grep audit: `grep -rn 'var(--color-primary-on)' apps/social/src/styles/` shows remaining uses are icons/avatars only.

## Out of scope

- The "saturated green text on light green tint" sites (separate issue, not reported).
