refactor: extract file sharing — IPFS audit + import + share ops (Step 13b)

Step 13b of the refactor plan. The File Sharing section is large,
so we split it: 13a covered simple list/publish; 13b covers the
audit-event-aware and library-import operations.

13b extracts 12 methods to node-service-fileshare.ts:
  - exportLibraryItemToIpfsViaRuntime
  - pinLibraryItemExternalViaRuntime
  - verifyLibraryItemIpfsGatewayViaRuntime
  - getIpfsEngineStatusViaRuntime

  - openLibraryItemViaRuntime
  - revealLibraryItemInFileManagerViaRuntime
  - listAgentShareProposalsViaRuntime

  - submitAgentShareProposalViaRuntime

FileShareContext extended with 3 new accessors:
  - getTaskStore() — used by the audit-event check that mirrors the
    pre-extraction class behaviour ("Task store not initialized
    — node is not fully wired")
  - getRagService() — used by getRagIndexStatusViaRuntime (the original
    class calls rag?.getIndexStatus(); the runtime preserves that
    behaviour — this is the fix that prevents the document acquisition
    E2E from regressing)
  - appendAuditEvent() — used by the IPFS pin path to record the
    "vault.ipfs_pin.completed" audit

Two dead helpers removed from the class:
  - _agentShareProposalStore field (no longer needed; runtime creates
    its own store internally via createAgentShareProposalStore())
  - _getAgentShareProposalStore() private method (also obsolete)

A new private _appendAuditEvent(event) helper was added to the class
to back the appendAuditEvent context field. It preserves the
"no-op when _taskStore is null" behaviour.
