refactor: extract share.preview inbound handler (Step 21a)

Step 21a — extract the simplest of the ~8 intent dispatchers
inside _handleInboundMessage. This is the first of several
extractions that will incrementally decompose the 400-line
handler body into per-intent runtime functions.

  - share.preview handler (~20 lines) -> handleSharePreviewViaRuntime

The handler's body is preserved (parseSharePreviewPayload,
recordInboundPullSharePreview, linkOutboundSharePreviewFromInbound).
The runtime takes a small SharePreviewContext interface with the two
class methods needed. The class side gets a `_sharePreviewContext()`
factory that wraps `this.recordInboundPullSharePreview` and
`this.linkOutboundSharePreviewFromInbound`.

Subtle coercion: `previewPayload.previewText` is `string | undefined`
but the class method signature expects `string`. The runtime coerces
with `?? ""` to preserve type safety — same semantic as the
original code, just explicit.
