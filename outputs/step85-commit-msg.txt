refactor: fix broadcast.response taskStore regression (Step 85)

The Step 71 broadcast.* patch silently dropped the `taskStore`
parameter from the call to `handleInboundBroadcastResponse`. The
inner function REQUIRES `taskStore` to append an audit event:

    await taskStore.appendAuditEvent(createAuditEvent({ ... }));

Without it, the call throws inside the try block, the catch returns
`{ok: false, reason: "invalid broadcast.response payload: ..."}`,
and the runtime logs a warn about an "invalid payload" when in
reality the payload was fine — we just never recorded the audit.

In production this means: every successful broadcast.response would
emit a spurious warn to the operator + a misleading audit event
("invalid broadcast.response payload: cannot read properties of
undefined"). The original index.ts code passed `taskStore` explicitly
and never had this issue.

This was the same class of bug that bit knowledge.query in Step 84
(missing context method, not missing argument). My audit script
catches the former but not the latter.

Fix:
  - broadcast.ts: read taskStore from ctx.getTaskStore?.(); if
    undefined, skip the response path (matches the original's
    crash-on-undefined behavior).
  - broadcast.test.ts: add `getTaskStore` to the mock so the response
    path actually runs.
