Step 20e — Option B as agreed: extract the wiring structure to a
runtime, leave the handler bodies as class methods.

What changed:
  - New runtime: apps/node/src/node-service-wire-mesh-events.ts
    - wireMeshEventsViaRuntime(ctx) registers the inbound-message and
      peer-discovered handlers with the mesh
  - Class `_wireMeshEvents()` is now a 3-line delegation

    the handlers
  - Class `_handleInboundMessage(params)` preserves the original 200+-
    line onMessage body verbatim, with `const mesh = this._mesh!;`
    etc. added at the top to mimic the original closure captures
  - Class `_handlePeerDiscovered(params)` preserves the original
    3-line onPeerDiscovered body

Net effect on line count:

    than the original because the factory + local-const declarations
    add a small amount of overhead)
  - node-service-wire-mesh-events.ts: 33 lines (new runtime)
  - Total project size: roughly unchanged (~12,610 lines combined)

Why this matters more than line count:
  - The wiring pattern (mesh.onX(handler) registration) is now
    encapsulated in a testable runtime

    per-intent runtime incrementally

etc. local captures are preserved as local consts at the top of
the new methods. This means the body code (`mesh.X`,
`profile.X`, etc.) continues to work without text substitution.
