refactor: extract persistence stores module (Phases 23 + 25D)

Step 5 of the node-service-impl.ts extraction plan. Per the
"module by module" feedback, this commit groups two related
local-JSON-file persistence features into a single runtime module
that owns the in-memory state (unlike prior steps where the class
retained the state).

- New runtime module: apps/node/src/node-service-persistence.ts (224 lines)
  - IntentHistoryStore class:
    - record(intent, query) — push + cap-oldest eviction
    - persist() — best-effort JSON write, errors logged
    - loadFromDisk() — silent no-op when file missing
    - getHistory() — defensive copy
    - clear() — drop in-memory entries
  - PublishedLibraryStore class:
    - publish({ title, topicTags, sensitivity? }) — append to "local"
    - setForPeer(ownerId, entries) — replace + backfill publishedAt
    - getEntries(ownerId?) — per-owner or all
    - getTopicsForContact(ownerId) — union of topicTags
    - persist() / loadFromDisk() / clear()
  - Shared `FileBackedStoreDeps` with getFilePath() + optional now()
  - buildIntentHistoryFilePath / buildPublishedLibraryFilePath helpers
- Class fields replaced: `_intentHistory` -> `_intentHistoryStore`,
  `_publishedLibrary` -> `_publishedLibraryStore`.
- Class methods reduce to 1-3 line delegations.
- predictIntent() at line 11371 now reads via `_intentHistoryStore.getHistory()`.
- node-service-impl.ts: 14038 -> 13965 lines (-73)
- 19 new unit tests cover:
  - file-path helpers
  - IntentHistoryStore: eviction, injected now(), persist no-op when
    no path, persist+load round trip, no-file load, maxEntries
    cap on load, clear()
  - PublishedLibraryStore: default + explicit sensitivity,
    setForPeer replace + backfill, getEntries all/per-owner,
    defensive copy, getTopicsForContact union + unknown owner,
    persist+load round trip, clear()
